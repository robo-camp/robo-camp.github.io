Remember what you did?:
Learning Behavioral Memories for Partially Observable Object Manipulation

Anonymous Authors
Under Review

Overview

From 0% to 70% success: a compressed memory of past actions resolves partial observability. Many manipulation tasks are partially observable, so memoryless policies act on an aliased signal and fail on tasks like Push-T-Multi-Goals (left). CAMP (right) pretrains a memory module ℰθ to reconstruct the past action trajectory, yielding a compressed code z that conditions a diffusion action head and turns the partially observed problem Markovian.

Abstract

Long-horizon, multi-stage manipulation tasks are often partially observable: a single visual observation rarely captures a robot's full action context, including prior attempts, interactions, or progress. Consequently, standard visuomotor policies, vision-language-action models, and world-action-models are prone to struggle in such tasks due to a lack of memory. To address this, we introduce Compressed Action Memory Policy (CAMP) based on the insight that a robot's own action history serves as a highly informative, self-supervised signal, enabling the policy to learn a robust, compact history representation. In our approach, we train a memory module to maintain a compressed representation of past actions, forcing it to encode a latent behavioral memory of all the robot's past interactions that can then be used to better contextualize future actions. This allows our approach to implicitly track generalized task progress and learn from failed attempts without any additional supervision, or external oversight. We evaluate CAMP on two novel simulation benchmarks, Memory-T-Bench and Memory-Manip-Bench, on the external RMBench, and on four real-robot tasks. By demonstrating substantial gains over state-of-the-art baselines, CAMP is, to our knowledge, the first policy to demonstrate substantial success on partially observable manipulation tasks purely through learned behavioral memory.

Memory-T-Bench

Memory-T-Bench comprises four PushT-derived tasks that share the same contact-rich dynamics but cannot be solved from a single frame. Three are track-task-progress tasks -- the policy must remember what it has already accomplished -- and one is a learn-from-failure task, where it must remember what did not work. Because a single observation hides what the robot has already tried or achieved, a memoryless policy stalls; by compressing its own action history into a compact behavioral memory, CAMP recovers this hidden state -- effectively closing the partial-observability gap.

RMBench

RMBench is an external dual-arm memory benchmark of nine tasks, with 50 demonstrations per task and evaluation on unseen layouts. Seven are track-task-progress tasks and two (Battery-Try and Blocks-Ranking-Try) are learn-from-failure. Hover a card for details.

Success: the object matching the hidden target is picked up.

Rearrange-Blocks
Track Progress▾

Fill the originally empty mat, then place the second block between the mats -- recalling which mat was empty at the start.

Success: both blocks end in the required spots.

Put-Back-Block
Track Progress▾

Carry the block to the center pad, press the button, then return the block to the pad it came from -- which the current frame no longer reveals.

Success: the block is back on its original pad.

Swap-Blocks
Track Progress▾

Exchange two blocks via a spare basket; their original positions are not visible mid-episode.

Success: each block ends in the other's starting position.

Swap-T
Track Progress▾

Exchange two T-blocks whose original positions are not visible mid-episode.

Success: each T-block ends in the other's starting pose.

Battery-Try
Learn from Failure▾

Insert two batteries whose correct polarity is hidden, flipping only the ones that were rejected.

Success: both batteries are inserted with the correct polarity.

Blocks-Ranking-Try
Learn from Failure▾

Order three blocks of unknown rank by swapping pairs and pressing a check button, using each verdict to avoid repeating a failed arrangement.

Success: the check button confirms the correct order.

Cover-Blocks
Track Progress▾

Cover three blocks with identical covers, then re-open them in a prescribed color order -- remembering what lies under each cover.

Success: the covers are lifted in the prescribed color order.

Press-Button
Track Progress▾

Read two number cards and press each button exactly that many times before confirming -- counting its own presses.

Success: each button is pressed the shown number of times, then confirmed.

Trained from scratch, CAMP reaches the best average success of 52.3% -- 10.6 points above the best prior method -- with 100% on Rearrange-Blocks, Put-Back-Block and Blocks-Ranking-Try and 97% on Battery-Try.

The memory gap is even larger on the real robot. Every memoryless baseline (ACT, DP, π0.5) scores 0/10 on Push-T-Multi-Goals, Swap-Can, and Wipe-Plate, while CAMP reaches 7/10 on each. A bounded history window recovers only part of the gap: LDP fails on every task, and CDP succeeds only on Swap-Can (3/10) and Probe-Insert (7/15). CAMP is the only method that consistently completes all four tasks.

Limitations and Conclusion

We introduced CAMP, a memory-augmented visuomotor policy for long-horizon, multi-stage manipulation under partial observability that turns the robot's own action history into a scalable, self-supervised learning signal. CAMP demonstrates consistent gains across Memory-T-Bench, Memory-Manip-Bench, RMBench, and multiple challenging real-robot tasks.

Limitations remain. Tasks requiring extremely-long-horizon memory are still challenging for our method. Thus, extending CAMP to support such long-horizon memory is a natural avenue for future work.
